# STATUS — Verstak

Обновлено: 2026-07-27.

## Текущее состояние

- Версия приложения в исходниках: `2.2.1`.
- Последний тег: `v2.2.1` (`316c90a`), есть на `origin`. Публикация установочных
  файлов в GitHub Release на 26.07 не подтверждена readback'ом.
- Основная ветка: `main`, синхронизирована с `origin/main`.
- Волна 2.2 закрывает скорость: параллельная подготовка контекста, одна сборка
  CLI payload, покадровый batch стрима и lazy-loading вторичных экранов.
- 2.2.1 закрыт: durable-счётчики пула подписочных аккаунтов в Настройках,
  живое состояние чата в боковой панели (точка больше не врёт), удаление
  тройного хранения состояния чата и мёртвых символов.
- 2.1.2 Durable Agent Control Plane закрыт, включая модульный runtime делегирования.
- 2.1.3 управление подписками, аккаунтами, fallback lineage и расходом находится
  в `main`.
- 2.1.4 Model Gym закрыт: 30 детерминированных fixture-задач, role policy,
  адаптеры Verstak/Codex/OpenCode, воспроизводимый Arena-отчёт и release gate.
- 2.1.5 Outcome Mode закрыт: единый вход «До результата», три уровня глубины,
  durable-прогон, экран плана/jobs/маршрута/проверок/Proof и локальные метрики.
- 2.1.6 закрыт: durable-история прогонов по проекту, фильтры состояния и
  открытие старого результата без повторного обращения к модели.
- 2.1.7 закрыт: в истории собраны требующие человека jobs с безопасными
  cancel/resume/apply/reject и обязательным readback состояния.
- 2.1.8 закрыт: Markdown-паспорт результата из main-owned данных, системный
  Save As, redaction секретов/путей и readback записанного файла.
- 2.1.13 Memory lifecycle закрыт: срезы `pre-compress` и `session-end` сохраняют
  решения, факты и долги вместо сырого transcript; сырой автозахват
  (`auto_capture_memory`) переведён в opt-in.
- 2.2.2 Supply-chain закрыт разбором по достижимости: production advisories
  17 → 4. Оставшиеся четыре — цепочка `@huggingface/transformers` без
  upstream-фикса и без достижимого пути в коде Verstak; это пин с триггером
  пересмотра, а не задача.
- PerChatState закрыт полностью: срез 4.4 влит коммитом `ef4af73`, `chats` —
  единственный SSOT состояния чата.
- 2.1.10 декомпозиция agent runtime — срезы A–G выполнены, пакет закрыт. Ядро
  agent-loop разнесено по `ai/runner-*.ts`; из `ai:send` вынесены
  Outcome-preflight, выбор провайдера и модели, pre-flight подписочного аккаунта,
  fallback-маршрут, бухгалтерия прогона с таймаутом, IPC управления прогоном
  (`ipc/ai-resolve.ts`) и — срезом G — вся сборка контекста и промпта
  (`ipc/ai-send/{memory-context,system-assembly,provider-options,run-input}.ts`).
  `electron/ipc/ai.ts` 1569 → 1104 строк, тело `ai:send` 842 → 694. В хендлере
  осталась оркестрация прогона, а не сборка.

## Открытый остаток

- **2.1.11 декомпозиция renderer (P1).** Выполнены: срез A (`PolicyTab`),
  периферия композера (`chat/ComposerSkillBar`, `chat/ComposerBudgetBar`,
  `chat/system-slash-commands`) и ядро композера (`chat/ComposerInputRow`).
  Размеры на 27.07: `Chat.tsx` **3869**, `Settings.tsx` 4649, `layout.css` 21994.
  Остаток пакета: часть 2 среза B — нижняя строка композера (`gg-composer-hint` +
  `gg-composer-meta`, ~247 строк), затем срез C (stream rendering), срез D
  (pipeline controls), вкладки Settings, деление CSS, UI smoke. Границу тестового
  харнесса и раскладку остатка см. в аудите, раздел 2.1.11.
- **2.1.12 остаточный долг (P2).** TODO второй ветки незакрытой review-сессии в
  `electron/ipc/agent-runs.ts`; lazy-импорты в `App.tsx`, которые сборщик всё
  равно включает статически; рантайм-флаги (`memory_lifecycle`,
  `auto_capture_memory`, `smart_routing`, `smart_fallback`, `use_project_brain`)
  не выведены в UI — решать разом для всех, не только для памяти.

Подробности и история срезов — `docs/CODE-AUDIT-2026-07-25.md`.
