# Задача 5 — Память vs Откат: фактическая карта + варианты (грунтовка под /pavel-ux-ui)

Павел ждал от раздела «Память» точку отката. Откат в продукте ЕСТЬ, но он о нём не
знает — потому что «память» и «откат» в Verstak это ТРИ разные вещи, свалённые под
одно слово в голове пользователя. Ниже — честная карта, чтобы предложение не врало.

## Что реально есть (три системы, не одна)

### 1. Core Memory — «всегда в промпте» (`electron/ai/core-memory.ts`)
- Файлы `.verstak/MEMORY.md` (заметки о проекте) + `.verstak/USER.md` (о пользователе).
- ВСЕГДА инжектится в system prompt на КАЖДОМ ходу. Агент правит через
  `core_memory_append/replace/remove`. Лимиты: MEMORY 2000 симв, USER 1500.
- С 03.08 (VSK п.6, коммит `1da0364`) заводится при открытии проекта — раньше файлов
  не было до первого core_memory_* и «память не работала».
- В UI СЕЙЧАС отдельного показа этих файлов, похоже, нет (панель показывает не их).

### 2. Архивная память — таблица `memories` (`electron/storage/memories.ts`)
- Типы: факт / решение / баг / предпочтение / паттерн. Ищется ОДИН раз за app-сессию
  (не каждый ход, в отличие от core).
- **Это и показывает панель «Память»** (`src/components/MemoryGovernance.tsx`, view
  `memory-gov`): ревью авто-запомненного, keep/edit/reject. Цель — не дать агенту молча
  засыпать память мусором.

### 3. Откат правок — НЕ память вовсе (живёт в чате/прогоне)
- Per-file undo stack: `electron/storage/undo.ts` + `electron/ipc/undo.ts` (UndoEntry с
  provenance — какой прогон/ход изменил файл).
- Сессионный checkpoint: `agent_run_checkpoints` (resume + откат целой агентной сессии).
- Кнопка отката сессии (`CheckpointButton`), откат прогона к git-якорю (Control Envelope,
  в инспекторе). exact-rewind отдаёт сырые backups (память `verstak-exact-rewind-raw-backups`).
- **Пользователь этого не находит**, потому что искал в «Памяти», а откат — в чате и в
  «Истории работы AI».

## Суть проблемы (для критики /pavel-ux-ui)
«Память» — слово-ловушка: пользователь читает его как «то, что помнит система, и куда
можно вернуться». Мы под ним показываем ТОЛЬКО архивную таблицу (#2), а самое ожидаемое —
откат (#3) — прячем в другом месте, и постоянные заметки (#1) не показываем вообще.

## Варианты развода на честные имена (на выбор Павла, до кода)
- **V1 — Память = только память, но честно и полностью + указатель на откат.**
  Панель переименовать в «Память ИИ» с двумя явными частями: «Постоянные заметки»
  (core-файлы #1, редактируемые) + «Архив запомненного» (#2). Вверху баннер: «Нужно
  вернуть правки назад? → Откат живёт в истории прогона», ссылкой открывающий Задачу-1
  раздел. Откат НЕ переносим — только делаем находимым.
- **V2 — «Память и откат» одним зонтиком, две вкладки.** Вкладка «Что помнит ИИ»
  (#1+#2) и вкладка «Точки возврата» (#3: список undo/checkpoints с откатом). Ближе к
  ожиданию Павла, но смешивает два разных концепта под одним пунктом меню.
- **V3 — Разнести и подписать.** «Память ИИ» (#1+#2) остаётся; откат (#3) поднимается
  как видимая функция в «Историю проекта» (Задача 1, вкладка Обзор: кнопка «Откатить
  правки прогона» уже есть — сделать заметной) + в чате у сообщения. Память и откат
  честно РАЗДЕЛЕНЫ, оба находимы.

Рекомендация исполнителя: **V3** (не врёт, что откат — это память; переиспользует уже
существующие точки отката; ложится на Задачу 1). Но это зона вида — выбор Павла.

Зависимость: пересекается с Задачей 1 (откат прогона уже в инспекторе → в «Историю
проекта»). Финальный вид гнать через /pavel-ux-ui после go Павла.
