# Mode C — разведка сессии CLI (позиция 1 плана 2026-07-27)

Дата: 2026-07-27. Исполнитель: dev-hq. Приёмка: FAST.
Статус: **ЧАСТИЧНО** — механика сессии проверена живьём и вопрос «умеет ли CLI»
закрыт; цифры input-токенов по ходам НЕ сняты, упёрлись в авторизацию (см. §5).

Кода в этой позиции не написано — ни строки. Ниже только измерения и вердикт.

## 1. Что проверяли

Сегодня каждый ход CLI-провайдера сериализует **всю** историю чата в one-shot
`--print`. Вопрос: умеет ли установленный `claude` держать сессию между ходами и
сколько это экономит.

Зафиксированная версия: **`claude 2.1.207 (Claude Code)`**, бинарь
`/c/Users/Pavel/.local/bin/claude`.

## 2. Что делает Verstak сейчас (сверено с кодом)

- `electron/ai/claude-cli.ts:183` — argv ровно
  `['--print', '--output-format', 'stream-json', '--verbose']` (+ `--model`,
  + guard-флаги режима). Флагов сессии нет: поиск `continue|resume|session-id|fork-session`
  по файлу даёт только два `continue` внутри циклов разбора потока.
- `electron/ai/cli-prompt.ts` — шапка модуля прямо декларирует допущение:
  «CLI providers in `stream-json` mode are effectively ONE-SHOT — they don't support
  multi-turn back-and-forth over a single stdin session. So we must serialize the
  conversation into the prompt itself.»
- `electron/ai/claude-cli.ts:158,200` — дочерний процесс запускается с `cwd` = корень
  проекта.

## 3. Что умеет установленный CLI (из `claude --help` этой версии)

| Флаг | Что делает |
|---|---|
| `-c, --continue` | продолжить последний разговор в текущем каталоге |
| `-r, --resume [value]` | продолжить разговор по session ID |
| `--session-id <uuid>` | задать конкретный session ID для разговора |
| `--fork-session` | при возобновлении создать новый ID вместо переиспользования |

То есть **допущение в шапке `cli-prompt.ts` для `claude-cli` устарело**. Оно, возможно,
верно для других CLI-провайдеров, но не для этого.

## 4. Живой прогон: механика сессии подтверждена

Один и тот же 3-ходовой диалог прогнан двумя плечами в нейтральном каталоге.
Плечо A — как Verstak сейчас: каждый ход заново сериализует историю в один
`--print`. Плечо B — нативная сессия: ход 1 с `--session-id <uuid>`, ходы 2–3 с
`--resume <uuid>`.

Результат по идентичности сессии (поле `session_id` в ответе CLI):

| Плечо | Ход 1 | Ход 2 | Ход 3 | Итог |
|---|---|---|---|---|
| A — one-shot | `4762af8d…` | `a28db11d…` | `64532679…` | **три разных** — каждый вызов отдельный контекст |
| B — сессия | `f0da1450…` | `f0da1450…` | `f0da1450…` | **один и тот же** — сессия принята и удержана |

Подтверждение из локальных транскриптов CLI
(`~/.claude/projects/<escaped-cwd>/<session-id>.jsonl`):

- плечо A — **три отдельных файла**, в каждом по 1 user-реплике, и в этой реплике
  лежит вся сериализованная история с префиксами «Пользователь: … Ассистент: …»
  (ровно то, что делает `buildCliPrompt`);
- плечо B — **один файл**, 22 строки, **4 user-реплики**: три наши плюс служебная
  `Continue from where you left off.`, которую вставляет сам `--resume`.

Вывод участка: `--resume` — настоящее продолжение, CLI перечитывает прошлый транскрипт
и дописывает в него, а не начинает с чистого листа.

## 5. Чего снять НЕ удалось и почему

Цифры input-токенов по ходам не получены: дочерний процесс `claude` в этом окружении
не авторизован — все шесть вызовов вернули `Not logged in · Please run /login`,
`usage` во всех нулевой. В окружении нет ни `CLAUDE_CODE_OAUTH_TOKEN`, ни
`ANTHROPIC_API_KEY`, ни `ANTHROPIC_AUTH_TOKEN`. Логинить CLI и доставать сохранённый
токен из настроек Verstak исполнитель не стал намеренно: это работа с чужими
учётными данными.

**Как доснять за одну команду.** В авторизованном терминале, из любого пустого
каталога, скрипт ниже печатает таблицу «ход → input / cache read / cache write /
output» по обоим плечам. Он ничего не пишет в репозиторий.

```js
// recon.mjs — запуск: node recon.mjs
import { spawn } from 'node:child_process'
import { randomUUID } from 'node:crypto'

const TURNS = [
  'Перечисли 10 российских городов-миллионников списком, только названия, без комментариев.',
  'Из этого списка выбери три самых южных. Только названия, без комментариев.',
  'Для первого из этих трёх городов назови федеральный округ. Ответь одним словом.',
]

const run = (args, stdin) => new Promise(res => {
  const c = spawn('claude', args, { shell: true })
  let out = ''
  c.stdout.on('data', d => { out += d })
  c.on('close', () => { try { res(JSON.parse(out)) } catch { res({ usage: {}, result: out.slice(0, 200) }) } })
  c.stdin.write(stdin); c.stdin.end()
})

const row = (arm, turn, j) => {
  const u = j.usage ?? {}
  console.log([arm, turn, u.input_tokens ?? 0, u.cache_read_input_tokens ?? 0,
    u.cache_creation_input_tokens ?? 0, u.output_tokens ?? 0, j.total_cost_usd ?? 0].join('\t'))
}

console.log('плечо\tход\tinput\tcacheRead\tcacheWrite\toutput\tusd')

const hist = []
for (let i = 0; i < TURNS.length; i++) {
  const payload = hist.length === 0 ? TURNS[i]
    : hist.map(h => `Пользователь: ${h.q}\nАссистент: ${h.a}`).join('\n\n') + `\n\nПользователь: ${TURNS[i]}`
  const j = await run(['--print', '--output-format', 'json'], payload)
  row('one-shot', i + 1, j)
  hist.push({ q: TURNS[i], a: (j.result ?? '').replace(/\s+/g, ' ').trim() })
}

const id = randomUUID()
for (let i = 0; i < TURNS.length; i++) {
  const args = i === 0
    ? ['--print', '--output-format', 'json', '--session-id', id]
    : ['--print', '--output-format', 'json', '--resume', id]
  row('session', i + 1, await run(args, TURNS[i]))
}
```

## 6. Что измерено вместо токенов: фиксированный префикс каждого хода

Считано по живым файлам репозитория, не по памяти:

| Часть, пересылаемая ЗАНОВО каждый ход | Символов | ≈ токенов (4 симв./токен) |
|---|---|---|
| `SYSTEM_LAYER_PROMPT` (`electron/ai/system-layer.ts`) | 5 478 | ≈ 1 370 |
| `CLAUDE.md` как user_layer | 18 429 | ≈ 4 610 |
| **Итого фиксированный префикс** | **23 907** | **≈ 5 980** |

Сверх этого каждый ход несёт растущую историю, context pack и, при активном скилле,
`<skill_layer>` с контрактом соблюдения.

**Отдельная находка — `CLAUDE.md` уезжает дважды за ход.** `cliReadsLayerNatively`
(`electron/ai/cli-prompt.ts:42`) захардкожена в `false`, то есть Verstak всегда
инжектит user_layer в payload; при этом дочерний `claude` стартует с `cwd` = корень
проекта и по умолчанию сам подхватывает `CLAUDE.md` (справка `--bare` перечисляет
`CLAUDE.md auto-discovery` среди того, что `--bare` отключает, — значит в обычном
режиме она включена). ≈ 4 600 токенов дублируются на каждом ходе. Это дешёвая
отдельная правка, не требующая Mode C.

## 7. Вердикт

**Строим — но сначала доснять §5.** Обоснование:

1. Техническая возможность есть и проверена живьём: `--session-id` + `--resume` на
   версии 2.1.207 держат один контекст между вызовами.
2. Допущение, на котором построен текущий одноразовый путь, для `claude-cli` неверно —
   это дефект документации кода, который надо поправить независимо от Mode C.
3. Но экономическая часть вопроса открыта. `--resume` доказанно восстанавливает
   контекст; **сколько при этом уходит по проводу — не измерено**. Возможны два
   исхода: сессия действительно не пересылает историю, либо пересылает её же, но
   попадает в prompt cache. В первом случае выигрыш большой, во втором — заметно
   скромнее и достигается частично уже сейчас. Ставить реализацию до этих цифр значит
   гадать о размере выигрыша.

**Рекомендуемый порядок:** (а) доснять таблицу §5 одной командой в авторизованном
терминале; (б) отдельной дешёвой задачей убрать двойную отправку `CLAUDE.md` (§6);
(в) решать по Mode C уже с цифрами на руках.
