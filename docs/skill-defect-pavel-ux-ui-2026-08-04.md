# Дефект скилла `/pavel-ux-ui` — молча не делает обещанного (факт для Павла)

Зафиксировано 2026-08-04 по просьбе штаба. НЕ чинить здесь — скиллы зона Павла,
правятся через `/skill-workshop`. Это запись-факт, не задача.

## Что скилл обещает
`/ux-ui` (он же `/pavel-ux-ui`, адаптеры: `C:\Users\Pavel\.codex\skills\pavel-ux-ui`,
`C:\Users\Pavel\.claude\skills\ux-ui`) — дизайн-студия. Оба режима (ПРОТОТИП и ПРИЁМКА)
в своих инструкциях говорят: **«Запустить `agent-ux-ui` через спавн субагента»** —
экспертиза, craft-правила и рендер/критика через Playwright живут в этом субагенте.
Success-критерий скилла прямо гласит: «Работу выполнил `agent-ux-ui` через спавн
субагента — скилл сам HTML не писал».

## Чего не хватает в рантайме
В рантайме этого исполнителя субагент `agent-ux-ui` / `pavel-agent-ux-ui` **недоступен**:
в списке спавнящихся типов Agent-тула его нет (есть только general-purpose/Explore/
Plan/claude и т.п.). То есть скилл роутит в исполнителя, которого нет.

## Последствие (тот же класс, что галочка «больше не спрашивать»)
Скилл ВЫГЛЯДИТ рабочим — загружается, печатает инструкции, — но молча не делает того,
что обещает: некому отрендерить экран, выставить баллы по живому виду и достроить
визуал. Критику пришлось собирать вручную по его рубрике (`references/critique-rubric.md`),
и она вышла СТРУКТУРНОЙ (по коду), а не по рендеру — что прямо противоречит правилу
самого скилла «критика только по тому, что реально видно на скрине». Мокапы задач 5 и 6
собраны исполнителем напрямую, а не субагентом.

## Что решать (Павлу / через /skill-workshop)
- Либо завести/зарегистрировать `agent-ux-ui` в рантаймах, где скилл вызывается;
- либо в скилле предусмотреть честный фолбэк, когда субагента нет (и СКАЗАТЬ об этом,
  а не молчать), — чтобы «выглядит рабочим» перестало расходиться с «делает обещанное».
