## Ждёт Павла / решения постановщика

### 1. Состояние «Папки с документами»: one-shot vs «держится проектом»
- **Что ждёт:** финальное решение о поведении вооружения код-сводки материалов.
- **Почему без него/вестака:** продуктовый выбор поведения, есть развилка.
- **Сделано вокруг:** реализован и запушен **one-shot** (вооружение на одну
  следующую отправку, снимается на отправке/смене чата/смене проекта). Причина
  отхода от «держится проектом»: при персисте «не открывал N» кричало бы на
  каждом follow-up, где модель не перечитала все документы, — тот шум, ради
  устранения которого сводка молчит на «прочитано N из N». Флаг отправлен вестаку.
- **Решение одной строкой:** оставить one-shot ИЛИ переиграть на персистентный
  per-project флаг (осознанный шум на follow-up; меняется одним местом в
  `send-chat-message.ts` + хранение per-project).

### 2. Живая приёмка A1 «Первая задача» — тремя людьми
- **Что ждёт:** три человека-не-разработчика проходят сценарий «выбрал папку →
  „собери отчёт с таблицей и сохрани DOCX рядом“ → получил открывающийся файл».
- **Почему без него нельзя:** приёмка целевой аудиторией не имитируется.
- **Сделано вокруг:** весь конвейер построен и пиноват по частям (папка/вложения/
  xlsx/сводка/DOCX-назначение). Сквозной живой прогон «диалог → прогон → строка»
  тестами не закрыт по построению.
- **Решение одной строкой:** организовать трёх тестировщиков, снять результат.

### 3. Смена партиции браузера (этап 0 → рабочая сессия агента)
- **Что ждёт:** Павел разлогинивается, замер партиции при закрытом приложении,
  список доменов с его логинами — сюда.
- **Почему без него нельзя:** в текущей партиции его живые логины; трогать нельзя.
- **Сделано вокруг:** (заполняется в блоке 3).
- **Решение одной строкой:** подтвердить домены и разрешить отдельную чистую
  партицию для агента.

### 4. Живой прогон этапа 3 браузера в личной почте Павла
- **Что ждёт:** доказательство работы в его реальном Chrome с логинами.

## Ждёт Павла — добавлено по ходу

### 5. Изображение принимается композером, но материалом не считается
- **Что ждёт:** решение, нужен ли ОТКАЗ на приложенную картинку.
- **Почему без него нельзя:** продуктовый выбор (вкус/поведение).
- **Сделано вокруг:** `.png` композер берёт (accept), но в набор материалов
  (док-типы) картинка не входит и в код-сводку не попадает. На дешёвой модели без
  зрения картинка молча не даёт пользы — человек НЕ УЗНАЕТ, что она бесполезна.
- **Решение одной строкой:** оставить как есть ИЛИ показывать отказ/подсказку на
  изображение в контексте задачи с документами.

### 6. Сквозной живой прогон A1 «диалог → выбор папки → отправка → строка сводки»
- **Что ждёт:** живой прогон, тестами не закрыт по построению.
- **Три пункта проверки (дословно, чтобы пройти по списку, а не вспоминать):**
  1. выбрать реальную папку с документами → папка ОТКРЫЛАСЬ как проект;
  2. при непрочитанном моделью документе → всплыла СТРОКА СВОДКИ («в корне N,
     прочитано K, не открывал …»);
  3. follow-up в том же чате → строка НЕ повторяется (one-shot).

## Решения исполнителя (автономные, к сведению — не блокеры)

### Блок 3 браузер: транспорт снимка — executeJavaScript сейчас, CDP для сети/headless
- **Что:** структурный снимок с нумерацией, клик/ввод по номеру, ожидание, чтение
  КОНСОЛИ строятся на существующем `executeJavaScript` (page-side DOM-walk) —
  тестируется в jsdom, идёт через `browserHandler` (гейты SEC-CMD на пути).
- **Что честно требует CDP/main-процесса (следующий инкремент):** чтение СЕТИ и
  работа БЕЗ открытой вкладки (headless webContents), разделение партиции.
  Постановка говорила «через CDP» — но ядро ценности (дерево+номера+клик+ожидание)
  достижимо и тестируемо без CDP уже сейчас; CDP заменит транспорт для сети/headless.
- **Инвариант требования №1 (номера протухают после навигации → честная ошибка)
  реализуется в этом же ядре и покрыт пином** — не откладывается на CDP.

### Блок 3 инкремент 1 — СДЕЛАНО (снимок+номера+клик-по-номеру), нужен живой прогон
- **Сделано и под гейтом:** `shared/browser-snapshot.ts` (ядро, 7 jsdom-пинов,
  протухание номеров доказано мутацией); инструменты `browser_snapshot` (чтение) и
  `browser_click_by_number` (мутация) через тот же `browserHandler`; SEC-CMD-06 на
  НОВОМ пути (клик-по-номеру в plan не доходит до страницы, снимок — доходит) —
  2 новых пина зелёные потому, что новый путь под категорией-списком
  `MUTATING_BROWSER_TOOLS`, а не потому, что старый жив; журнал не врёт (снимок/клик-
  по-номеру помечены поимённо, не «скриншот»).
- **ЖДЁТ ЖИВОГО ПРОГОНА (сквозной, доказывается только живьём):** инжекция
  `vskSnapshot/vskResolveNumbered` в реальный webview через
  `executeJavaScript((${fn.toString()})(...))`. jsdom доказал ЛОГИКУ функций; что
  бандлер сохраняет `.toString()` пригодным к инжекту и что реальная страница
  отдаёт снимок/кликает по номеру — проверяется открытием вкладки Browser и
  прогоном «snapshot → click_by_number → навигация → устаревший номер = ошибка».
- **Что решит Павел одной строкой:** открыть Browser, дать агенту «сделай снимок и
  нажми N-й элемент», убедиться в честной ошибке после навигации.
- **Осталось на CDP-инкремент:** ввод по номеру (type_by_number), ожидание элемента,
  чтение КОНСОЛИ (можно и на executeJavaScript-хуке), чтение СЕТИ и headless (нужен
  CDP/main), разделение партиции (решение Павла, журнал п.3), этап 2 (dev-сервер
  через run_command → порт → открыть → консоль → стоп).
