# execute_code (PTC) — прогон, где инструмент выбирает МОДЕЛЬ

Дата: 2026-07-28. Исполнитель: dev-hq (ночной прогон). Волна 0, блок 2.

## Статус: ПРОГОН НЕ ВЫПОЛНЕН — блокер интерфейса, не модели

Живой прогон, где модель сама вызывает `execute_code`, **не состоялся**. Скриншотов
Timeline нет по той же причине. Ниже — точная природа блокера, а не общее «не
получилось»: она другая, чем ожидала постановка, и это меняет способ закрыть пункт.

Код продукта не тронут: `electron/ai/ptc.ts`, дефолт флага и `system-layer.ts` не
изменялись; ни одного файла в `electron/`, `src/`, `tests/`.

## 1. Блокер: почему прогон невозможен в этом окружении

Постановка предполагала цепочку «`npm run dev` → Settings → включить `ptc_enabled` →
дать задачу в чате». Каждое звено, кроме первого, требует **действий мышью в окне
приложения**. Исполнитель работает в текстовом окружении и управлять GUI Electron не
может: ни включить тумблер, ни отправить сообщение в чат, ни снять скриншот Timeline.

**Важно — модель доступна.** Это не блокер авторизации. Расшифровка настроек внутри
Electron показала, что рабочие API-провайдеры настроены: DeepSeek, Kimi, custom
OpenAI-совместимый и Verstak Gateway (значения ключей нигде не печатались). То есть
живой агентный прогон в принципе возможен — упирается именно в интерфейс.

**Обходной путь проверен и не годится.** В репозитории есть headless-агент
`scripts/verstak-cli.mjs` — самодостаточный запуск без Electron. Он подошёл бы, но
инструмента `execute_code` у него нет: набор ограничен девятью тулзами
(`read_file`, `list_directory`, `search_project`, `find_files`, `get_project_map`,
`write_file`, `apply_patch`, `run_command`, `review_before_commit`). Модель не может
выбрать инструмент, который ей не предложен, поэтому через headless-путь пункт
закрыть нельзя в принципе — не «не получилось», а нечем.

PTC живёт только в Electron-пути: хендлер `electron/ipc/tool-handlers/execute-code.ts`
регистрируется в `HANDLER_REGISTRY`, а предложение тулзы модели гейтится в
`electron/ai/runner-api.ts` по `ptc_enabled`.

## 2. Что уже доказано и переоткрывать не нужно

Из аудита 27.07 (коммит `8668f4c`, `tests/ai/execute-code-live-loop.test.ts`, 10 пинов):

- **петля работает на настоящих файлах:** скрипт читает шесть реальных файлов через
  реальные read-only тулзы (`createFileTools`), агрегирует и возвращает только итог;
  итог в контексте **более чем в 10 раз** короче суммы сырых tool-результатов, и
  содержимого файлов в нём нет вовсе;
- **периметр закрыт:** в песочнице ровно пять read-only тулзов, список под пином;
  `write_file`, `apply_patch`, `run_command`, `connector_query`, `web_fetch`,
  `delegate_task` внутрь не попадают — проверено и по списку, и изнутри скрипта
  (`typeof tools.write_file === 'undefined'`);
- **права не шире `run_command`** во всех пяти режимах агента — пин параметризован:
  в `plan` блок, в `ask` подтверждение человеком;
- **гейт по умолчанию** закреплён пином на исходник `runner-api.ts`.

То есть три из четырёх проверок пункта 3 постановки (блокировка в `plan`, approval в
`ask`, недоступность тулзов вне пяти read-only) **уже покрыты автоматически** и
зелёные. Не покрыто ровно одно — что модель выберет инструмент сама, и что в Timeline
это видно человеку.

## 3. Что осталось непроверенным

| Проверка из постановки | Состояние |
|---|---|
| Модель сама вызывает `execute_code` | **не проверено** — нужен GUI |
| В Timeline виден вызов и агрегированный результат | **не проверено** — нужен GUI |
| В режиме `plan` вызов блокируется | покрыто пином (`8668f4c`) |
| В режиме `ask` требуется approval | покрыто пином (`8668f4c`) |
| Внутри песочницы нет тулзов вне пяти read-only | покрыто пином (`8668f4c`) |

## 4. Как закрыть пункт за один сеанс

Действия человека за компьютером, ~10 минут:

1. `npm run dev`;
2. Настройки → AI → «Поведение агента» → включить «Программное исполнение кода»
   (`ptc_enabled`). Перезапуск не нужен: значение читается на каждом прогоне;
3. выбрать провайдера, где ключ заполнен (DeepSeek / Kimi / Gateway), режим `auto`;
4. дать задачу, где агрегация выгодна, например: «прочитай все файлы
   `electron/connectors/*.ts` и посчитай количество экспортов в каждом, ответь
   таблицей»;
5. в Timeline посмотреть, появился ли `execute_code` и агрегированный итог;
6. если за три попытки с разными формулировками модель инструмент не выбрала —
   **это тоже результат**: записать формулировки и что она делала вместо этого
   (скорее всего — серия `read_file`). Промпт-инжинирингом не выдавливать.

Условие включения по умолчанию остаётся прежним и не смягчается: **один прогон, где
модель выбрала инструмент сама**.

## 5. Рекомендация одной строкой

**Оставить opt-in. Причина: живого прогона с выбором инструмента моделью по-прежнему
нет, а исполнение произвольного кода — внешний эффект, который включают по факту, а
не по ожиданию.** Периметр доказан, петля доказана, риска в выключенном состоянии
инструмент не несёт — ждать одного сеанса дешевле, чем включать вслепую.
