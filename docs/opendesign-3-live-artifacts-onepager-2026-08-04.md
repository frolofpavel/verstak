# Open Design #3 — «Live Artifacts»: это АВТОМАТИЗАЦИЯ, а не новая фича (Павел отклонил, и он прав)

Обновлено после решения Павла. Прежняя версия оценивала это в 5–8 дней MVP как подсистему —
это была ОШИБКА оценки: мы собирались построить второй контур рядом с уже существующим.
Не отложенная большая ценность — обнаружено, что она уже есть.

## Довод Павла (принят целиком)
«Это рекламная тонкая боль, многим может быть не надо» и «это обычная автоматизация — её и
так можно сделать». По существу: всё, из чего складывается Live Artifact, У НАС УЖЕ ЕСТЬ.

## Из чего оно складывается — и что из этого уже готово
| Кусок Live Artifact | В Verstak | Статус |
|---|---|---|
| Данные из внешних систем | 31 read-only коннектор (Метрика/Директ/Ozon/WB/amoCRM/МойСклад…) | ✅ есть |
| Пересборка отчёта | генерация артефактов (generate_html / render_chart) | ✅ есть |
| «Раз в неделю» | Расписание (задача 8) | ✅ есть |
| Показать клиенту | встроенное превью | ✅ есть |
Итог: «раз в неделю пересобрать отчёт из коннектора» — это ЗАДАЧА ПО РАСПИСАНИЮ, а не подсистема.

## Что НЕ покрывается автоматизацией (только это — и это путь+строка, не механизм)
1. **Стабильный адрес вывода** — чтобы у клиента не менялась ссылка при каждой пересборке
   (фиксированный путь артефакта задачи, а не новый файл каждый раз).
2. **След обновлений в журнале** — строка «отчёт X обновлён, источник Y, N строк» при каждом рефреше.

## Оценка
**~1 день.** Задача по расписанию (существует) + стабильный путь вывода (одна настройка пути)
+ запись в журнал при обновлении (одна строка через recordJournal). Никакого нового формата
шаблона, никакого fail-closed-слоя, никакой подсистемы.

## Вывод (чтобы следующий читатель не ошибся)
Мы НЕ отложили большую ценность — мы обнаружили, что она уже есть как автоматизация. Если
кому-то из клиентов нужен авто-обновляемый отчёт: расписание + стабильный путь + запись в
журнал. Называть это «фичей Live Artifacts» — вводить в заблуждение; это применение того,
что построено. Пересекается с headless-линией (серверный рефреш логично там) — свести, не дублировать.
