# Mode C — цифры по нативной сессии Claude CLI

Дата: 2026-07-28. Исполнитель: dev-hq (ночной прогон). Волна 0, блок 1.

## Статус: ЗАМЕР ПО ТОКЕНАМ НЕ СНЯТ — блокер авторизации

Главный вопрос блока — «экономит ли нативная сессия input-токены или выигрыш только
в prompt cache» — **остался без ответа**. Ни один из 18 запланированных вызовов не
выполнен: установленный `claude` не авторизован, а добывать учётные данные ночью
запрещено правилами.

Что при этом снято и годится для решения — в §3: фактические размеры payload по
ходам. Это **потолок** возможной экономии, измеренный на том самом трёхходовом
диалоге из постановки. Сколько из этого потолка реально превратится в неоплаченные
токены — по-прежнему неизвестно.

Код продукта не тронут: ни одного изменённого файла в `electron/`, `src/`, `tests/`.

## 1. Блокер: диагностика по всем путям

Проверены все способы авторизации, которые не требуют вводить учётные данные:

| Путь | Результат |
|---|---|
| Сам CLI | `claude -p` → `is_error: true`, `Not logged in · Please run /login` |
| Штатный файл учётных данных claude CLI | отсутствует |
| `ANTHROPIC_API_KEY` в окружении | не задан |
| `CLAUDE_CODE_OAUTH_TOKEN` в окружении | не задан |
| `ANTHROPIC_AUTH_TOKEN` в окружении | не задан |
| **OAuth-токен, сохранённый в Verstak** (`claude_code_oauth_token`) | **строка в хранилище есть, значение ПУСТОЕ** |

Последняя строка — самая содержательная. Verstak умеет прокидывать дочернему
`claude` переменную `CLAUDE_CODE_OAUTH_TOKEN` из своих настроек (это заявлено в
`CLAUDE.md`, раздел V3-фич). Ключ в хранилище заведён, но пуст: поле в Настройках
когда-то сохранили, не заполнив. Расшифровка выполнена внутри Electron с профилем
Verstak; значение нигде не печаталось и на диск не писалось.

Это тот же класс, что уже описан в `docs/connectors-audit-2026-07-27.md` §0:
наличие строки в настройках не означает наличия значения.

**Что разблокирует блок за одно действие.** Любое из двух, на выбор:

1. в терминале выполнить `claude` → `/login` (после этого CLI авторизован, и
   команда из §4 отработает как есть);
2. либо заполнить поле OAuth-токена в Настройках Verstak — тогда заработает и
   штатный проброс в дочерний процесс, и ночной харнесс.

## 2. Что уже было доказано (не переоткрывать)

Из `docs/cli-session-recon-2026-07-27.md`, подтверждено живым прогоном 27.07 на
`claude 2.1.207`:

- нативная сессия **есть**: `-c/--continue`, `-r/--resume`, `--session-id`,
  `--fork-session`;
- `--session-id` + `--resume` удержали **один** `session_id` на три хода, а локальный
  транскрипт накопил все реплики плюс служебную `Continue from where you left off.`;
- одноразовое плечо для сравнения породило **три разных** `session_id` и три
  отдельных транскрипта по одной реплике;
- значит `--resume` — настоящее продолжение, а не новый контекст.

Механика доказана. Экономика — нет.

## 3. Что снято этой ночью: размеры payload по ходам

Диалог ровно из постановки, три хода, история наращивается:

1. «прочитай electron/ai/cli-prompt.ts и перескажи назначение»
2. «какие функции экспортирует»
3. «что в шапке файла устарело»

Путь А — то, что Verstak делает сейчас: на каждом ходе `buildCliPrompt` собирает
полный конверт (system layer + user layer + context pack + сериализованная история)
и отправляет его целиком одним `--print`. Путь Б — нативная сессия: на ходах 2–3 в
CLI уходит только новый вопрос, контекст уже лежит в сессии.

Замер сделан вызовом настоящего `buildCliPrompt` на реальном корне репозитория.

| Ход | Путь А (как сейчас) | Путь Б (сессия) |
|---|---|---|
| 1 | 33 478 байт ≈ 8 370 ток. | 85 байт ≈ 21 ток. |
| 2 | 34 392 байт ≈ 8 598 ток. | 50 байт ≈ 13 ток. |
| 3 | 34 843 байт ≈ 8 711 ток. | 48 байт ≈ 12 ток. |
| **Итого** | **102 713 байт ≈ 25 678 ток.** | **183 байта ≈ 46 ток.** |

**Честная трактовка, а не рекламная.** Строка «ход 1, путь Б = 85 байт» —
арифметика, а не реальность: на первом ходе любая реализация обязана отправить
конверт целиком, иначе агент не получит ни правил проекта, ни контекста. Поэтому
корректный потолок экономии считается по ходам **2 и 3**:

- одноразовый путь пересылает на них 34 392 + 34 843 = **69 235 байт**;
- сессия отправила бы 98 байт;
- **потолок экономии ≈ 69 137 байт ≈ 17 284 токена на диалог**, то есть
  **≈ 8 650 токенов на каждый ход после первого**.

Оценка токенов здесь — деление байтов на 4, а не показания API. Обозначено «≈»
намеренно: настоящих чисел от модели у нас нет.

## 4. Как доснять недостающее одной командой

После авторизации CLI (см. §1) харнесс ниже выполняет ровно то, что требовал блок:
3 хода × 2 пути × 3 повтора, снимая `input_tokens`, `cache_read_input_tokens`,
`cache_creation_input_tokens`, латентность и размер отправленного payload.

```js
// tokens.mjs — запуск: node tokens.mjs   (в авторизованном терминале)
import { spawn } from 'node:child_process'
import { randomUUID } from 'node:crypto'

const Q = [
  'прочитай electron/ai/cli-prompt.ts и перескажи назначение',
  'какие функции экспортирует',
  'что в шапке файла устарело',
]
const REPEATS = 3

function run(args, stdin) {
  return new Promise(res => {
    const t0 = Date.now()
    const c = spawn('claude', args, { shell: true })
    let out = ''
    c.stdout.on('data', d => { out += d })
    c.on('close', () => {
      // stream-json: последняя строка типа result несёт usage
      let last = null
      for (const line of out.split('\n')) {
        if (!line.trim()) continue
        try { const j = JSON.parse(line); if (j.type === 'result') last = j } catch { /* чанк */ }
      }
      res({ ms: Date.now() - t0, bytes: Buffer.byteLength(stdin, 'utf8'), u: last?.usage ?? {}, sid: last?.session_id })
    })
    c.stdin.write(stdin); c.stdin.end()
  })
}

const SJ = ['--print', '--output-format', 'stream-json', '--verbose']
console.log('повтор\tпуть\tход\tbytes\tinput\tcacheRead\tcacheCreate\toutput\tms')

for (let r = 1; r <= REPEATS; r++) {
  // Путь А — одноразовый, история сериализуется в payload (как cli-prompt.ts)
  const hist = []
  for (let k = 0; k < Q.length; k++) {
    const payload = hist.length === 0 ? Q[k]
      : hist.map(h => `Пользователь: ${h.q}\nАссистент: ${h.a}`).join('\n\n') + `\n\nПользователь: ${Q[k]}`
    const x = await run(SJ, payload)
    console.log([r, 'one-shot', k + 1, x.bytes, x.u.input_tokens ?? 0, x.u.cache_read_input_tokens ?? 0,
      x.u.cache_creation_input_tokens ?? 0, x.u.output_tokens ?? 0, x.ms].join('\t'))
    hist.push({ q: Q[k], a: '(ответ)' })
  }
  // Путь Б — нативная сессия
  const id = randomUUID()
  for (let k = 0; k < Q.length; k++) {
    const args = k === 0 ? [...SJ, '--session-id', id] : [...SJ, '--resume', id]
    const x = await run(args, Q[k])
    console.log([r, 'session', k + 1, x.bytes, x.u.input_tokens ?? 0, x.u.cache_read_input_tokens ?? 0,
      x.u.cache_creation_input_tokens ?? 0, x.u.output_tokens ?? 0, x.ms].join('\t'))
  }
}
```

**Как читать результат.** Смотреть на ходы 2–3 пути `session`:

- `input_tokens` там **мал** (сопоставим с длиной вопроса) → история по проводу не
  уходит, экономия реальная. Вердикт: «экономия реальная: N токенов/ход»;
- `input_tokens` **велик**, но почти весь ушёл в `cache_read_input_tokens` → история
  пересылается, платим по льготной цене кэша. Вердикт: «выигрыш только prompt cache»,
  и тогда часть выигрыша у нас уже есть сегодня;
- разброс между повторами перекрывает разницу между путями → «статистически
  неразличимо».
