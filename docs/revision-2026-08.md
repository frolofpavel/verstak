### 3.2 Список секрето-путей: `secret-scanner` ↔ `claude-cli` — уже РАЗОШЁЛСЯ

Комментарий в `electron/ai/claude-cli.ts:69` объявляет `SECRET_GLOBS` «зеркалом
`isForbiddenPath`». Сверка списков:

| Что | API-путь (`isForbiddenPath`) | CLI (`SECRET_GLOBS`) |
|---|---|---|
| `id_rsa` / `id_ed25519` / `id_ecdsa` / `id_dsa` вне `.ssh/` | запрещено (basename) | **разрешено** (глоб только `.ssh/**`) |

| `.envrc` | запрещено (`basename.startsWith('.env')`) | **разрешено** (`**/.env.*` не матчит `.envrc`) |

- **Цена:** приватный ключ, лежащий в корне проекта (обычное дело после `ssh-keygen -f ./id_rsa`),
  Claude Code прочитает штатным `Read`, тогда как API-путь его закрывает.
- **Стража нет:** единственный тест пары описан в §2.10 «б» и расхождение не видит.
- **Куда свести:** генерировать глобы ИЗ списков `secret-scanner` (basenames → `**/имя`,
  dirs → `**/dir/**`, extensions → `**/*.ext`), а не поддерживать вторую редакцию руками.

- **Что видит человек:** первый экран установщика, плитка «**18** провайдеров моделей».
  Число неверно уже сейчас. Та же устаревшая цифра — в `CLAUDE.md` §1 («18 провайдеров:
  база 10 + 8 OpenAI-совместимых»), фактически 11 + 11.
- **Стража нет** — ни один тест не связывает константу с реестром.
- **Куда свести:** считать из `PROVIDER_IDS.length` (или из явного продуктового списка,
  если 22 — не то число, которое Павел хочет показывать; тогда решение о числе за ним,
  но оно должно быть ОДНО и проверяемое).

### 3.4 Записи `CLAUDE.md` §5, пережившие свою правду

§5 перечисляет пятерых «кандидатов на переезд, пока держать синхронно». Проверено:

| `PRICES` | переехал в `shared/contracts/pricing.ts`, дубля нет |

## 4. ДОДЕЛАТЬ ИЛИ ЗАКРЫТЬ

### 4.1 `TODO`/`FIXME` в коде — ноль

Проверено по `electron/`, `src/`, `shared/`, `scripts/`, `mobile/`: ни одного `TODO`,
`FIXME`, `XXX`, `HACK` в качестве маркера незавершённости (все совпадения — тексты
промптов и описания инструментов). Направление «незаконченное» через этот признак пустое;
всё, что найдено ниже, найдено другими признаками.

### 4.2 PTC (`execute_code`) — подсистему невозможно включить из интерфейса

- **Факт.** Гейт `getSecretForDelegate?.('ptc_enabled') !== 'true'` (`runner-api.ts:961`).
  Строка `ptc_enabled` во всём `src/` **не встречается ни разу** — переключателя нет
  ни в «Поведении агента», ни в «Правах модели», нигде. Включить можно только правкой
  строки в `settings` руками.
- **Возраст.** Фича внесена **24.06** (`5b50e76`), последний раз тронута 25.06. Полтора
  месяца в состоянии «построено, выключено, включить нечем».
- **Объём:** `electron/ai/ptc.ts` (120) + `electron/ipc/tool-handlers/execute-code.ts` (58)
  + 3 тест-файла.
- **Стережёт это ТЕКСТОВЫЙ пин:** `tests/ai/execute-code-live-loop.test.ts:214` проверяет
  `expect(src).toContain("getSecretForDelegate?.('ptc_enabled') !== 'true'")` — сверка
  строки исходника, а не поведения.
- **Решение Павла:** либо тумблер в `RUNTIME_FLAGS` (одна строка таблицы + подпись) и
  живая проверка петли, либо закрыть и удалить.

### 4.3 `docs/live-check-list-pending.md` — файл, переживший свою правду

Шапка файла: «Статус: **ОТДАН** 05.08.2026», отметок о прохождении внутри нет — читается
как незакрытый долг. Факт: соседний `docs/live-check-list-2026-08-08-evening.md` прямо
пишет, что этот список **Павел прошёл 08.08 на 2.4.4**. То есть работа закрыта, а имя
файла (`-pending`) и его шапка продолжают утверждать обратное — ровно тот класс, который
§3.1 регламента велит снимать тем же движением, что закрывает позицию.

**Закрыть:** переименовать/пометить пройденным либо удалить. Цена — минута; цена
бездействия — следующий читатель заведёт работу, которой нет (я на этой записи
споткнулся в этой же ревизии).

### 4.4 Из §2 — то, что решается кодом теста, а не продуктом

Десять позиций §2 — это не «фича сломана», а «фича не доказана». Дешёвая закрывающая
работа: по одному тесту на КАЖДЫЙ вызов гейта в бою (harness `tests/ipc/agent-loop.test.ts`
и `tests/ipc/command-gating.test.ts` уже умеют это делать — по их образцу и писать).
Ориентир: 10 тестов, каждый обязан краснеть на мутации из §2 — мутации выписаны дословно
и воспроизводимы. Самая дешёвая из них — MCP (§2.3 и §2.11): один тест-файл на
`mcpToolHandler` закрывает сразу две позиции, потому что сейчас этот файл не импортирует
ни один тест.

## 7. Ограничения метода — читать до того, как опираться на списки

1. **Граф ссылок построен по идентификаторам, а не по разрешению модулей.** Файл,
   упоминающий имя в комментарии, считается ссылающимся. Из-за этого граф ПРОПУСКАЕТ
   мёртвое (так `GATEWAY_PRESET_LABELS` не попал в автоматический список — его нашли
   руками). Обратной ошибки (объявить живое мёртвым) метод почти не даёт, но каждая
   строка §1 всё равно перепроверена сырым `grep` по всему дереву.
2. **Зелёная мутация = нет теста, а не «фича сломана».** Продукт в бою может работать
   правильно; ревизия утверждает ровно одно — регрессию в этом месте никто не заметит.
3. **Мутациями покрыты не все ключевые модули.** Не тронуты: провайдеры и стримы,
   автообновление, встроенный браузер, миграции БД, delegation/swarm, skills, headless-сервер.
   Каждый — отдельная партия того же метода.
4. **Условия прогонов названы.** Все замеры — в отдельном worktree
   (`.claude/worktrees/dazzling-neumann-10b004`), полные прогоны `--maxWorkers=4`,
   собрано 5463 из 5463 (полнота сверена с эталоном), падений по памяти не было.
   `node_modules` — junction на главное дерево; `npm ci` не запускался (CLAUDE.md §3.1).
