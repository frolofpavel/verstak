# Враждебное ревью Verstak 2.6.4

**Дата:** 2026-08-16 · **Версия:** 2.6.4 (коммит `82ae6a1`, `release/Verstak-Setup-2.6.4-x64.exe`, 335 МБ)
**Роль рецензента:** разработчик, который каждый день работает в Cursor и Claude Code. Внутренней истории проекта не знает. Судит по тому, что видит.
**Заказ:** найти, за что продукт разнесут, ДО того как это сделают чужие.

**Стенд.** Установка с нуля в изолированный каталог (`--silent --install-dir=…\hostile-review\app`), запуск с изолированным профилем (`--user-data-dir=…\hostile-review\profile`). Профиль и установка Павла не тронуты (проверено: 23 файла, 55 локалей на месте, процессы живы). Все ярлыки и запись в «Установка и удаление программ», перехваченные моей установкой, восстановлены.

**Чего в отчёте нет — и это честная дыра.** Живого прогона задач на DeepSeek не было: секреты шифруются os_crypt-ключом профиля и в изолированный профиль не переносятся, а профиль Павла я не трогал. Прогнано то, что доказывается без ключа: путь новичка целиком, встроенный браузер (реальная навигация + чтение страницы), панели проекта, установка/обновление. Пункт «5 типовых задач на живом провайдере» закрыт **частично** — см. §«Что осталось непроверенным».

**Скриншоты:** `docs/hostile-review-2026-08/`.

## За что уничтожат

### 1. Обновление поверх запущенного приложения уничтожает установку. Насовсем

Самый дорогой пункт отчёта. Сайт учит: «Скачайте .exe → Запустите → Готово». Ровно так человек и поставит новую версию — не закрывая программу.

**Что происходит** (воспроизведено дважды, второй раз намеренно):

1. Установщик копирует пейлоад поверх работающей копии, упирается в залоченный файл и падает: `EPERM: operation not permitted, unlink '…\Verstak\d3dcompiler_47.dll'`. В GUI это показано пользователю **как есть** — сырой текст ошибки Node.js на экране выбора папки ([01-installer-eperm.png](hostile-review-2026-08/01-installer-eperm.png)). В silent-режиме — просто `exit=1`, молча.
2. Дальше срабатывает «откат» — `rollbackInstall()` в [electron/installer/engine.ts:193](../electron/installer/engine.ts#L193). При `ownDir=true` он делает `rm(installDir, {recursive:true, force:true})`. То есть **откат здесь означает «удалить», а не «вернуть как было»**. Возвращать не к чему: старая версия уже затёрта копированием.
3. `rm` спотыкается о занятые файлы (`Verstak.exe`, dll в работе) — и сносит всё остальное.

**Замер.** Каталог установки: было 22 записи, стало 11. Снесено: `resources.pak`, `chrome_100_percent.pak`, `chrome_200_percent.pak`, `icudtl.dat`, `snapshot_blob.bin`, `vulkan-1.dll`, скрипт удаления — и **весь `locales/` (0 файлов)**.

**Итог для человека.** `Verstak.exe` на месте, ярлык на рабочем столе на месте. Двойной клик — **не открывается ничего**. Ни окна, ни ошибки, ни строки в логе: `logs/runtime.jsonl` в свежем профиле не создаётся вовсе. Что именно так и будет, проект знает сам — комментарий в [scripts/build-setup.cjs:44-48](../scripts/build-setup.cjs#L44) описывает, что без locale-pak рендер Chromium падает `0xC0000005` и это уже стоило трёх версий с серым окном.

Проверки «приложение запущено» в установщике нет: `grep` по `engine.ts` не находит ни `tasklist`, ни `Get-Process`, ни `isRunning`, ни обработки `EBUSY/EPERM`.

**Честная граница.** Встроенное авто-обновление этим не болеет: хелпер ждёт выхода родителя (`waitForProcessExit(parent-pid)`, [scripts/verstak-auto-update-helper.cjs:272](../scripts/verstak-auto-update-helper.cjs#L272)). Уязвим **ручной** путь — тот самый, который описан на сайте как основной.

> **Что скажет критик:** «Я скачал апдейт с их сайта, как они и написали. Программа перестала запускаться. Не откатилась, не предупредила — просто сдохла. Инсталлятор, который убивает рабочую установку и называет это откатом, — это не 2.6.4, это 0.6.4.»

### 2. Приложение тратит чужой API-ключ из переменных окружения и при этом пишет «не подключён»

В свежем профиле не сохранено ни одного ключа (таблица `settings`: `provider`, `model_gemini-api`, `app_language`, … — секретов нет). Индикатор в UI честно горит **«не подключён»**.

Я отправил первую задачу. Она **ушла в Google** и вернулась настоящим `403 PERMISSION_DENIED` ([05-first-task-403.png](hostile-review-2026-08/05-first-task-403.png)). Значит ключ был.

Откуда — [electron/main.ts:536-546](../electron/main.ts#L536):

```ts
const ENV_MAP: Record<string, string> = {
  gemini_api_key: 'GEMINI_API_KEY',
  anthropic_api_key: 'ANTHROPIC_API_KEY',
  openai_api_key: 'OPENAI_API_KEY',
  groq_api_key: 'GROQ_API_KEY',
  xai_api_key: 'XAI_API_KEY',
}
const getSecret = (key: string): string | null => {
  const stored = settings.getSecret(key)
  if (stored) return stored
  return process.env[ENV_MAP[key] ?? ''] ?? null   // ← молча
}
```

На стенде в окружении есть `GEMINI_API_KEY` (значение не печатал; длина 39), остальных четырёх нет. Совпадает с наблюдением ровно.

Три вещи в одном месте:
- **Индикатор врёт.** «Не подключён» — и одновременно авторизованный запрос за деньги владельца ключа.
- **Согласия не спрашивают.** У любого разработчика с Claude Code в окружении лежит `ANTHROPIC_API_KEY`. Verstak начнёт им платить, не показав ни строки об этом. Нигде — ни в README, ни в UI, ни в release notes — этот подхват не описан.
- **README прямо это опровергает:** «**No telemetry** — nothing leaves your machine except calls to the providers you configure» ([README.md:120](../README.md#L120)). Провайдера я не конфигурировал. Вызов ушёл.

> **Что скажет критик:** «Оно нашло мой `ANTHROPIC_API_KEY` в окружении и начало им платить, показывая при этом „не подключён“. Я даже не могу сказать, сколько оно уже потратило. Это не фича, это то, за что выкатывают CVE.»

### 3. Проект по умолчанию — весь домашний каталог. Агенту с 83 инструментами

Онбординг не спрашивает про проект. После кнопки «Начать работу» человек оказывается в проекте с корнем **`C:\Users\Pavel`** — всей домашней папкой.

Доказательства:
- таблица `projects` свежего профиля: `{"path":"C:\\Users\\Pavel","name":"Pavel","kind":"local"}`;
- `logs/runtime.jsonl`: `ai.runner.start … "projectPath":"C:\\Users\\Pavel" … "toolCount":83`.

Что из этого следует:
- Первый же прогон агента получает корнем `Documents`, `Desktop`, `Downloads`, `.ssh`, профили браузеров, рабочие репозитории.
- Открытие проекта **пишет** в этот корень: `ensureCoreMemoryFiles` создаёт `.verstak/MEMORY.md` и `USER.md` ([electron/ipc/projects.ts:145](../electron/ipc/projects.ts#L145)), `ensureUserLayer` ищет там же свои файлы. Никто не спросил.
- Панель «Мозг» автоматически проиндексировала домашний каталог: «**Проект из 5055 файлов. Прогрето 40 ключевых**», и все 40 «ключевых» — `.agents/skills/azure-deploy/references/recipes/*/README.md` ([06-brain-home-dir.png](hostile-review-2026-08/06-brain-home-dir.png)). Это витрина фичи «Мозг проекта» в первую минуту знакомства.
- «Карта проекта» на том же корне зависла на «Строю карту проекта…».

Да, `path-policy` закрывает `.env`, `*.key`, `.ssh`. Претензия не в том, что дыра — в том, что **область работы выбрал не человек**, и выбрал максимально широкую из возможных.

> **Что скажет критик:** «Оно молча назначило проектом мой `C:\Users\...`, проиндексировало 5055 файлов, записало туда свои .md и показало мне „мозг проекта“ из чужих Azure-рецептов. Cursor за десять лет не додумался открыть мне home как workspace.»

### 4. Release notes продукт мангалит сам — регекс-«облагораживателем» собственных текстов

Первое, что видит человек после установки, — модалка «Обновление установлено». В ней текст со сбитой пунктуацией: точка в середине фразы, дальше строчная буква.

Источник чист. `CHANGELOG.md` написан нормально, просто с переносами строк:

```
- **Защита секретов одинаковая на всех путях.** Приватные ключи и файлы с паролями
  в проекте закрыты одинаково, каким бы провайдером вы ни работали — …
```

Ломает [electron/release-notes-official.ts:26-42](../electron/release-notes-official.ts#L26): `formalizeReleaseBody` обрабатывает **каждую физическую строку отдельно**, и если строка похожа на пункт списка и не кончается на `.!?` — дописывает точку:

```ts
if (!/[.!?]$/.test(item) && item.length > 20) item += '.'
```

Перенос строки внутри пункта становится концом предложения. Продолжение приклеивается со строчной буквы.

**Прогон логики 2.6.4 по реальному `CHANGELOG.md`** (скрипт репродукции — в конце отчёта) даёт байт-в-байт то, что на экране:

```
…страница без ваших. входов и куки…
…объём, который агент. забирает со страницы…
…сообщение об ошибке. без текста…
…файлы с паролями. в проекте закрыты одинаково…
…намеренно ломая. код: десять защит…
…целый экран, оставшийся. от прошлой версии интерфейса…
```

**Шесть пунктов из шести.** Сто процентов релиз-нотов версии испорчены.

И тот же файл переписывает живую русскую речь по словарю регексов: `больше нет` → `отключено`, `тупит` → `не обрабатывает запрос`, `не видит` → `не получает`, а фраза про «жму — ничего не происходит» подменяется на заготовку «Добавлена прокрутка к целевому блоку настроек» — независимо от того, о чём был пункт.

**Почему это не поймали.** `tests/release-notes-official.test.ts` — четыре зелёных теста, и **во всех четырёх фикстура — однострочный пункт** (`'- Клик по коннектору скроллит к настройкам…'`). Продовый вход — многострочный, всегда. Тесты стерегут форму, которой в проде нет. Это буквально правило из собственного регламента проекта (`CLAUDE.md §3.1`, «тест, чья фикстура не совпадает с ПРОДОВОЙ формой вызова, не защищает ничего»).

> **Что скажет критик:** «У них в коде живёт регекс-редактор, который правит их же русский текст и расставляет точки по переносам строк. Они не вычитали единственный документ, который показывают каждому пользователю при каждом обновлении.»

### 6. Витрина обещает счётчики, которых продукт не подтверждает

Продукт продаёт себя цифрами — и все три расходятся с реальностью или между собой.

| Где | Что написано | Факт |
|---|---|---|
| Онбординг, первый экран ([02](hostile-review-2026-08/02-onboarding-ru.png)) | «**10+** AI-провайдеров в одном окне» | — |
| `README.md:25` | «### Providers (**18**)» | — |
| `shared/contracts/provider.ts` | — | **22** в `PROVIDER_IDS` |
| `README.md:93` | «### Connectors (**31**)» | 31 файл-адаптер; **живьём с настоящим ключом проверен один** |
| `README.md:63` | «**20+** tools» | **83** в рантайме (`runtime.jsonl: "toolCount":83`) |

Отдельно про счётчик провайдеров. Release notes 2.6.4 сообщают: «Из установщика и описаний **убран счётчик провайдеров**». В установщике — да, убран. Но `README.md` — главная публичная страница проекта — по-прежнему открывается разделом «Providers (18)», а первый экран приложения по-прежнему обещает «10+ провайдеров». **Пункт релиза не соответствует состоянию продукта.**

Про 31 коннектор. Собственный аудит проекта, [docs/connectors-audit-2026-07-27.md](connectors-audit-2026-07-27.md), формулирует честно и жёстко: «адаптеров написан 31, живьём с настоящим ключом проверен **один** (Метрика). Остальные 30 — код, который в бою никто не гонял». Витрина этой оговорки не содержит. Код при этом настоящий (130–500 строк на адаптер, официальные API, 32 файла тестов) — но «31 коннектор» на витрине читается как «31 работающая интеграция», а доказана одна.

> **Что скажет критик:** «Три разных числа провайдеров в трёх местах одного продукта. „31 коннектор“ — это 31 файл. Если они не могут посчитать собственные фичи, что ещё в этом списке — просто написано?»

## Стыдно, но переживём

**Первая задача новичка кончается сырым JSON.** Ответ на первое сообщение в жизни пользователя ([05](hostile-review-2026-08/05-first-task-403.png)):

```
[Ошибка: {"error":{"message":"{\n \"error\": {\n \"code\": 403,\n \"message\": \"Your project has been denied
access. Please contact support.\",\n \"status\": \"PERMISSION_DENIED\"\n }\n}\n","code":403,"status":"Forbidden"}}]
```

Двойной экранированный JSON, по-английски, человеку, которому продали «напиши обычными словами». Ниже — два блока ошибки подряд («Работа остановлена», «Ответ прерван») и кнопки «Повторить запрос заново / Показать что было / Отклонить». Повтор будет падать вечно: причина в доступе, а не в сети. Кнопки «Подключить модель» нет.

**Онбординг не доводит до работающей модели.** Экран находит на ПК Claude Code, Codex, Gemini CLI, Grok Build и предлагает «Подключить» — но пропустить можно всё, и человек попадает в чат с непровязанным провайдером по умолчанию. Шага «выбери модель» в мастере нет.

**Найденный инструмент без кнопки.** В том же списке пятая строка — `Hermes Agent v0.19.0` с зелёной точкой и **без кнопки «Подключить»** (проверено по DOM: у четырёх строк `<button class="gg-auth-connect">`, у пятой её нет). Продукт сообщает «нашёл» и не даёт ничего с этим сделать.

**«No telemetry» — неточная формулировка.** README: «nothing leaves your machine except calls to the providers you configure». На старте приложение ходит на `api.github.com` и `raw.githubusercontent.com` за обновлениями ([electron/update-remote.ts:127-185](../electron/update-remote.ts#L127)). Это не слежка — но фраза написана абсолютной и в этом виде неверна.

**Email собирают под фичу, которой нет.** Плейсхолдер поля: «для будущей облачной синхронизации». Собирать адрес под ненаписанную функцию — плохой тон, и это первое, что человек видит.

**«Known limitations (1.6.3)» в README версии 2.6.4.** Раздел ограничений заморожен на версии десятилетней давности по меркам этого репозитория. Читатель не может понять, что из списка ещё правда.

**Витрина без единого скриншота.** `docs/index.html` — лендинг десктопного приложения, в котором нет ни одного изображения интерфейса. Для продукта, который продаёт «видно каждый шаг», это выглядит как «боятся показать».

**Установщик просит закрыть тяжёлые приложения.** Текст на первом экране: «Перед установкой лучше закрыть другие тяжёлые приложения». Инсталлятор, который заранее извиняется за свою прожорливость, задаёт тон. (860,7 МБ на диске, 335 МБ загрузки — тоже заметно.)

**Вторая установка молча перехватывает ярлыки и запись об удалении.** Мой изолированный `--install-dir` переписал `Verstak.lnk` на рабочем столе, в меню «Пуск» и ключ `HKCU\…\Uninstall\ru.verstak.ide` — все они стали указывать на временную папку. Ключ один на приложение, проверки «здесь уже стоит другая копия» нет. (Восстановлено вручную.)

## Придирки

- **Пунктуация в интерфейсе.** Четыре пропущенные запятые перед «чтобы», и первая — на первом экране: `src/i18n/ru.ts:6` «Создай профиль**_**чтобы начать»; там же `:152` «Открой проект чтобы видеть задачи», `:288` «нажми чтобы открыть Настройки», `:307` «Перетащи чтобы изменить ширину».

Панель «Решения»: «**Запусти** /board». Сайт в одном абзаце: «для **твоей** работы» и «**Поставьте** задачу обычными словами».

## Неожиданно хорошо

Без этого раздела отчёт был бы нытьём. Вот что действительно сделано хорошо — проверено, не на слово.

- **Встроенный браузер — настоящий и быстрый.** Вызвал тот же API, который зовёт агент, без ключа и без модели: `navigate('https://example.com')` + `readPage()` → **495 мс**, реальный текст страницы. Это не заглушка, тракт работает целиком. Изолированная сессия из релиза 2.6.4 — не лозунг, а параметр инструмента с явным выбором среды (`electron/browser/isolated-session.ts`, `env: builtin|isolated` в схеме).
- **Панель «Память» — лучший экран продукта.** Честное пустое состояние («Пока пусто — здесь появится то, что агент запомнил, и вы сможете это проверить и поправить»), файлы `MEMORY.md`/`USER.md` открыто редактируются, и сразу оговорено, чем память **не** является: «Нужно вернуть правки назад? Это не память, а откат». Это уровень зрелости, которого нет у большинства.
- **Установщик как приложение — приятный.** Четыре внятных шага, прогресс, размер, выбор папки, регистрация в «Установка и удаление программ». Silent-режим с `--install-dir` есть и работает. Он падает на занятых файлах (§1), но по устройству это добротная вещь, а не обёртка над NSIS.
- **Инженерная дисциплина видна невооружённым глазом.** Релизный гейт с провенансом (`BUILD_PROVENANCE.json` сверяется с HEAD), сверка полноты прогона с эталоном (`EXPECTED_TOTAL_TESTS = 5596`), 5596 тестов / 1844 файла / 0 падений в артефакте релиза, 32 файла тестов на коннекторы. Комментарии в коде объясняют не «что», а **почему** — с датами инцидентов и ценой ошибки. Так пишут те, кто уже обжигался и сделал выводы.
- **Коннекторы написаны руками по официальным API**, а не скрейпингом: 130–500 строк на адаптер, read-only по умолчанию, ключи в `safeStorage`. И собственный аудит коннекторов написан честнее, чем витрина: он сам себя опровергает в §0. Это редкость.
- **Раздел «CLI vs API — honest scope» в README** прямо перечисляет, чего на CLI-провайдерах не будет. Продукт, который сам пишет границы своих возможностей, вызывает больше доверия, чем тот, который их прячет.

## Приговор

**Показывать разбирающимся людям в текущем виде нельзя** — и дело не в качестве инженерии, оно как раз выше среднего. Дело в том, что **первые пять минут продукта ломают доверие раньше, чем человек дойдёт до сильных мест.** Новичок последовательно получает: модалку «Обновление установлено» при первой установке, релиз-ноты с точками посреди фраз, интерфейс, где английский перемешан с русским, проект, назначенный на весь его домашний каталог, «мозг проекта» из чужих Azure-рецептов, первую задачу, умершую сырым JSON-ом с 403 — и при этом приложение уже потратило ключ, который человек не вводил и о котором ему не сказали. Ни один из этих дефектов не про «не успели сделать фичу»; все они про то, что **путь новичка ни разу не прошли от начала до конца чужими глазами**. 5596 зелёных тестов при этом ничего не заметили — и это главный диагноз: тесты стерегут код, который для них писали, а не продукт, который видит человек.

**Закрыть до показа — ровно четыре вещи, остальное подождёт:**

1. **Установщик не должен уничтожать работающую установку.** Проверка «приложение запущено» до первого удаления файла + отказ с человеческим текстом. И `rollbackInstall`, который восстанавливает, а не стирает, — либо не называется откатом. *(§1 — единственный пункт, который уже вредит реальным пользователям.)*
2. **Подхват ключей из окружения — либо выключить, либо показать.** Молча платить чужим `ANTHROPIC_API_KEY`, рисуя «не подключён», нельзя ни в каком виде. Минимум: явное «нашли ключ в окружении — использовать?» и честный индикатор. *(§2 — то, за что бьют больнее всего, потому что это про деньги и доверие.)*
3. **Первые пять минут пройти целиком, дважды — на русском и на английском.** Убрать «Обновление установлено» при первой установке, снять `formalizeReleaseBody` с релиз-нотов (он портит 6 пунктов из 6), довести онбординг до выбранной модели и **спросить про папку проекта** вместо назначения домашнего каталога. *(§3, §4, §5 — стоят одного дня и снимают половину отчёта.)*
4. **Привести счётчики в соответствие или убрать их.** «10+», «18», «22», «31», «20+» — пять чисел, ни одно не подтверждается. Решение по провайдерам уже принято и до `README.md` не доехало. *(§6 — дешевле всего и дороже всего по репутации: на счётчиках ловят первыми.)*

Пункты §7 (встроенные скиллы рекламного агентства, чтение чужих `~/.claude/skills`), английская локализация и вычитка текстов — следующая волна. Они делают продукт «чьим-то внутренним инструментом», но не убивают первую встречу.

Хорошая новость, которая в отчёт не поместилась целиком: под всей этой шелухой лежит настоящая инженерия — браузерный тракт, память, релизный гейт, честные внутренние аудиты. Верхний слой отстаёт от нижнего примерно на один сосредоточенный день работы. Сейчас разнесут именно за верхний.

## Приложение: как воспроизвести §4 за 30 секунд

Сохранить как `repro-notes.mjs` и запустить `node repro-notes.mjs CHANGELOG.md`. Тело функции — дословная копия `formalizeReleaseBody` из `electron/release-notes-official.ts` версии 2.6.4; последняя строка склеивает мягкие переносы так же, как это делает markdown в модалке.

```js
import { readFileSync } from 'fs'

function formalizeReleaseBody(body) {
  if (!body.trim()) return body
  let text = body.replace(/\r\n/g, '\n')
    .replace(/\s*[—–-]\s*«[^»]*»/g, '')
    .replace(/\s*\([^)]*(?:жму|ничего не|тупит|не вижу|раньше|было)[^)]*\)/gi, '')
  return text.split('\n').map(line => {
    const trimmed = line.trimEnd()
    if (!trimmed || trimmed === '---') return trimmed
    const bullet = trimmed.match(/^([-*]|\d+\.)\s+(.*)$/)
    if (!bullet) return trimmed                       // ← продолжение пункта уходит как есть
    let item = bullet[2].replace(/\s{2,}/g, ' ').trim()
    if (!item) return `${bullet[1]} `
    if (item[0] === item[0].toLowerCase() && /[а-яa-z]/.test(item[0])) item = item[0].toUpperCase() + item.slice(1)
    if (!/[.!?]$/.test(item) && item.length > 20) item += '.'   // ← вот здесь ломается
    return `${bullet[1]} ${item}`
  }).filter(Boolean).join('\n')
}

const md = readFileSync(process.argv[2], 'utf8')
const body = md.slice(md.indexOf('## 2.6.4'), md.indexOf('## 2.6.3')).split('\n').slice(1).join('\n').trim()
const seen = formalizeReleaseBody(body).replace(/\n(?!\s*[-*])\s*/g, ' ')
for (const m of seen.matchAll(/[а-яa-z]{3,}\. [а-яё]{2,}/g)) console.log('…' + m[0] + '…')
```

Ожидаемый вывод — шесть ложных точек, по одной на каждый пункт релиза:

```
…ваших. входов…    …агент. забирает…    …ошибке. без…
…паролями. в…      …ломая. код…         …оставшийся. от…
```
